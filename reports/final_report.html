1. Executive Summary

Demo này chứng minh 2 lỗ hổng bảo mật nghiêm trọng trên ứng dụng Android, bao gồm cả lớp Network và lớp Storage — tương ứng với yêu cầu bảo vệ Data in transit và Data at rest theo GDPR Article 32.

Scenario 1 — MITM Attack (VULN-001): App chấp nhận User-installed CA → Burp Suite intercept POST /api/login → username & password lộ dạng plaintext dù HTTPS. Fix: Network Security Config + Certificate Pinning.

Scenario 2 — Token Theft (VULN-002): App lưu JWT token vào files/token.txt dạng plaintext → ADB shell đọc trực tiếp không cần root → Attacker replay token để chiếm phiên đăng nhập. Fix: EncryptedSharedPreferences + Android Keystore + Root Detection.

2. Attack Chain — Kịch Bản Tấn Công Tổng Hợp

Hai lỗ hổng kết hợp tạo thành một attack chain hoàn chỉnh: kẻ tấn công có thể chiếm toàn bộ tài khoản chỉ bằng free tools (Burp Suite + ADB).

5. Remediation

5.1 Scenario 1 — Network Security Config + Certificate Pinning

Áp dụng res/xml/network_security_config.xml với cleartextTrafficPermitted="false", chỉ tin tưởng System CAs, và cấu hình Certificate Pinning SHA-256 trực tiếp trong XML (không phụ thuộc OkHttp).

Kết quả: App ném SSLHandshakeException khi phát hiện chứng chỉ không hợp lệ — Burp không nhận được request nào.

5.2 Scenario 2 — EncryptedSharedPreferences + Root Detection

Bước 1: Xóa token.txt khỏi internal files storage.
Bước 2: Lưu token qua EncryptedSharedPreferences (AndroidX Security, AES-256-GCM). Keys được quản lý bởi Android Keystore — không đọc được kể cả qua ADB hay root.
Bước 3: Thêm Root Detection: App tự động gọi finish() và xóa token khi phát hiện thiết bị bị root hoặc chạy trên emulator không tin cậy.

5.3 Scenario 3 — MFA: Đúng Thứ Tự Triển Khai

Phân tích quan trọng: MFA không đủ nếu transport layer chưa được bảo vệ.

Nếu thêm OTP mà chưa fix VULN-001: Burp intercept được cả POST /api/login lẫn POST /api/verify-otp — attacker relay OTP ngay lập tức trong cùng session window (30 giây). MFA hoàn toàn vô hiệu.

Thứ tự đúng:
  ① Fix transport → Network Security Config + Certificate Pinning (VULN-001)
  ② Fix storage → EncryptedSharedPreferences (VULN-002)
  ③ Thêm MFA → TOTP (Google Authenticator) hoặc Android Biometric Prompt

Sau khi transport đã secure, MFA mới thực sự có giá trị: bảo vệ trước credential stuffing, phishing ngoài MITM context.
